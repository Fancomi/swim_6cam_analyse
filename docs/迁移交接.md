# 迁移交接文档 — swim_6cam_analyse（Linux → Windows）

> 本文档供 **Windows 机器上的 Agent/开发者** 直接接手本项目。
> 项目已从 Linux 迁移到 Windows，代码完全一致，环境需在 Windows 重建。
> 阅读完本文档 + `README.md` + `cpp/README.md` 即可开始工作。

---

## 0. 项目一句话

六路相机拼接全景视频（5002×2102）的**游泳分析**：检测（yolo26 微调）→ 跟踪（IoU 贪心）→
RTMPose 关键点 → 划水计数与速度。提供 **Python 参考实现**（Plan A/B/C）与 **C++/CUDA 实时实现**
（Plan C 全链路 GPU 驻留，目标 71fps 纯分析 / 21fps 渲染）。

## 3. Windows 环境需求（C++ 链路）

| 组件 | 版本 | 说明 |
|---|---|---|
| Windows | 10/11 | 64 位 |
| Visual Studio | 2022 | 需装 "使用 C++ 的桌面开发" 工作负载 |
| CUDA Toolkit | 12.x | 与显卡驱动匹配；**50 系卡需 CUDA ≥12.8**（Blackwell） |
| TensorRT | **10.11.0.33** | 官方 Windows zip（与 Linux 版同版本，结构一致） |
| OpenCV | 4.x | 需要 core/imgproc/videoio/imgcodecs；建议带 CUDA 的构建（可选） |
| CMake | ≥3.18 | |

**TensorRT Windows 安装要点**：下载 `TensorRT-10.11.0.33.Windows.win10.cuda-12.x.zip`，
解压到 `C:/TensorRT-10.11.0.33`。注意 Windows 版 TRT 的库名带 `.lib`（`nvinfer.lib`、
`nvonnxparser.lib`），CMake 已用 `find_library(nvinfer)` 兼容。

**显卡架构参数**：`-DCMAKE_CUDA_ARCHITECTURES` —— RTX 40 系=`89`，RTX 50 系=`120`（sm_120），
RTX 30 系=`86`。**不要**用默认的 `86 89 90`（不含 50 系）。

### C++ 构建命令（Windows PowerShell）

```powershell
cd swim_6cam_analyse/cpp
cmake -B build -G "Visual Studio 17 2022" `
      -DTRT_ROOT=C:/TensorRT-10.11.0.33 `
      -DOpenCV_DIR=C:/opencv/build `
      -DCMAKE_CUDA_ARCHITECTURES=120
cmake --build build --config Release -j
```

> 若 OpenCV 未提供 CMake 包，可在 CMakeLists 里手动指定头文件/库路径，
> 或临时用 vcpkg 安装 opencv4。

### C++ 模型准备（Windows）

```powershell
# 用 venv 里的 Python 导出 fp16 ONNX（detect 必须 imgsz=640）
python cpp/tools/export_onnx.py --out cpp/models
# 首次运行自动构建 engine 并缓存到 cpp/models/*.engine
cpp/build/Release/swim_analyse.exe --input data/20260730/merged_3000f.mp4 --models cpp/models
```

> **engine 与 GPU 型号 + TRT 版本绑定**：Windows 上首次运行会重建（Linux 的 .engine 无用）。
> `detect.onnx`/`pose.onnx` 不在 git 里，必须在 Windows 上从 weights 重新导出。

## 4. Python 环境（Windows，参考实现用）

**Python 版本必须是 3.10**（mmcv 预编译 wheel 只提供 cp310）。

Linux 的 `install.sh` 用 bash + OpenMMLab 的 manylinux wheel，**Windows 不能直接用**。
Windows 安装步骤：

```powershell
# 1) 装 Python 3.10 (python.org)
# 2) 项目根目录
python -m venv .venv
.venv\Scripts\Activate.ps1

# 3) 先装 torch（CUDA 12.1 对应版）
pip install torch==2.1.0 torchvision==0.16.0 --index-url https://download.pytorch.org/whl/cu121

# 4) mmcv 预编译 wheel（Windows 版）
pip install "mmcv==2.1.0" -f https://download.openmmlab.com/mmcv/dist/cu121/torch2.1.0/index.html

# 5) 其余依赖（注意 numpy 锁 1.26.4，见 requirements.txt 头部注释）
pip install -r requirements.txt
pip install --no-deps mmpose==1.3.1
```

> **mmcv Windows 注意**：OpenMMLab 的 Windows wheel 较少，若上面 index 没有 win 版，
> 改用 `mmcv==2.1.0 -f https://download.openmmlab.com/mmcv/dist/cu121/torch2.1.0/index.html`
> 并选 win_amd64 条目；或降级 mmcv 用 CPU 版（`--no-build-isolation` 源码编译较慢，不推荐）。
> **优先用 C++ 链路**，Python 仅作参考/对照。

## 6. 已知事项 / 待办

1. **`--max-persons <40` 会崩**：pose engine 的 batch 上限在构建时固定（默认 40）。
   要支持低显存（如 20 人上限），需在 `main.cpp` 里把 engine 缓存文件名按 batch 参数化
   （如 `pose_b20.engine`），并在重建时用对应 opt/max batch 构建。4070/5070（12GB）上
   当前 40 人上限完全够用（实测每帧最多 13 人），非必须。
2. **NVDEC 未实现**：`frame_source.cpp` 里 `dlopen("libnvcuvid")` 是 Linux 写法，
   Windows 应改用 `LoadLibrary("nvcuda.dll"/"nvapi64.dll")` 探测；当前统一走 CPU 解码即可。
   纯分析瓶颈在 CPU 解码（19ms/帧），接上 NVDEC 可到 90-100fps。
3. **渲染模式瓶颈在 CPU H.264 编码**（21fps）：如需实时渲染，换 NVENC 或降渲染分辨率。
4. **`data/20260629/` 未打包**：Plan A（跨相机 mesh）需要它；Plan B/C 与 C++ 链路不需要。
5. **engine/onnx 不入库**：`cpp/models/*.onnx|*.engine` 在 .gitignore，Windows 首次运行
   自动从 weights 导出+构建。
6. **core 文件**：Linux 上 `core.3479244`（7.7G，崩溃转储）可删，不影响迁移。

## 7. 调试技巧（继承自 Linux 会话）

- **对照验证**：C++ `--dump` 导出逐帧框 → 与 Python 同参数重跑结果对比（两者应逐帧一致）。
  Python 侧 `output/merged_3000f/cache.pkl` 是**旧模型产物**，不要作为基准。
- **效率验证**：`--show-fps` 看实时帧率；GPU 占用用 `nvidia-smi`（Windows 同样有）。
- **显存**：C++ 全链路 GPU 驻留 + 显存预分配（零 cudaMalloc），应用占用 ~470MB；
  CUDA context 固定 ~523MB。12GB 消费卡跑多路无压力。
- **Windows 注意**：路径分隔符 `\`；bash 脚本（run.sh/install.sh）用 Git Bash 执行，
  或直接调 CLI 参数。
